# Проверка web-привязок на xhcc_s62

## Что проверяется

Сценарии отправляют JSON POST на **встроенный** `/rest.php` симулятора
контроллера, затем независимо читают фактические привязки через CAN.
CAN можно подключить напрямую или через существующий UDP-мост.
Браузер, JavaScript сайта и облачный сервер teplomonitor в этих тестах не участвуют.
Файлы `web/teplomonitor-server/config.php` изменять не нужно.

| ID | Сценарий | Последовательность |
| --- | --- | --- |
| 9.1.1 | Web: привязка входа программы | Вход программы 0 → локальный вход 0; повтор; перепривязка → вход 1; отвязка; повторная отвязка |
| 9.1.2 | Web: привязка реле контроллера | Реле 0 → выход программы 0; повтор; перепривязка → выход 1; отвязка; повторная отвязка |

Все индексы здесь **с нуля**: вход 0 и реле 0 обычно отображаются как первый
вход и первое реле в пользовательском интерфейсе.
После каждого шага читаются все 4 входа и 5 выходов тестовой программы,
а также все 11 реле контроллера. Проверяются ожидаемые изменения и неизменность
остальных привязок. Для реле проверяется и обратная привязка выхода программы.
Значения датчиков, срабатывание реле и сохранение привязок после перезагрузки
в этот первый набор не входят.

## Подготовка стенда

1. Использовать отдельный Qt-симулятор `xhcc_s62` без реальных нагрузок.
   Если нужна сборка, из `C:\development\SmartWeb`:

   ```powershell
   C:\Tools\Python311\scripts\scons.exe qtsim CFG_PROJECT=xhcc_s62 CFG_PLATFORM=qtsim --jobs=8
   ```

2. Запустить бинарник из `bin/xhcc_s62/`. Проверить в его настройках:
   IP-адрес, HTTP-порт, ID контроллера и включённый CAN-over-UDP с известным портом.
   Сценарий ожидает 18 входов и 11 выходов, как у xhcc_s62.
3. Отключить VPN, если он блокирует доступ. Открыть локальные web-страницы
   контроллера и проверить вход `admin/admin`.
4. Изолировать CAN-сегмент и UDP-порт: на них должен быть только выбранный
   тестовый контроллер. UDP-мост использует broadcast-обнаружение и может
   подключать несколько узлов. Один лишь web-IP **не фильтрует UDP-трафик**.
   Совпадение ID в HTTP/CAN — дополнительная проверка, не уникальный аппаратный ID.
5. Явно выбрать пресет `web_bindings` в Симуляторе Котельной.
   **Загрузка пресета удаляет текущие программы контроллера** и создаёт одну
   программу `DOUBLE_PUMP`, ID 101, без привязок и без виртуальных контроллеров I/O.
   Исходная конфигурация до загрузки пресета не сохраняется автоматически.

Сам сценарий не загружает пресет автоматически и не сбрасывает конфигурацию.
Он требует уже выбранный `web_bindings` и единственную тестовую программу в
HTTP-конфигурации выбранного контроллера. Выходы программы и тестовое реле 0
должны быть свободны; входы не должны ссылаться на другие программы.

## Запуск

Пример: web-адрес `http://192.168.1.50`, CAN-ID 7, UDP-порт 31987.
Заменить эти значения фактическими; автоматически они не угадываются.
Команды выполняются из корня `C:\development\BoilerRoomSimulator`.

Первый сценарий без GUI:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --no-gui --can virtual --udp 31987 --id 7 --profile web_tests --preset web_bindings --web-url http://192.168.1.50 --scenario C:\development\BoilerRoomSimulator\scenario\list\web\scenario_web_input_9_1_1.py
```

Второй сценарий:

```powershell
C:\Tools\Python311\python.exe main.py --no-gui --can virtual --udp 31987 --id 7 --profile web_tests --preset web_bindings --web-url http://192.168.1.50 --scenario C:\development\BoilerRoomSimulator\scenario\list\web\scenario_web_relay_9_1_2.py
```

Для GUI убрать `--no-gui`. После подготовки можно выбрать оба сценария в
диалоге сценариев и выполнить последовательно в одной сессии.
Прямой CAN: заменить `--can virtual --udp 31987` на нужный `--can <context>`.

По умолчанию используются логин `admin` и пароль `admin`.
Для другого пароля задать переменную окружения `BRS_WEB_PASSWORD` перед запуском;
имя переменной можно изменить через `--web-password-env`.
Логин меняется через `--web-login`, HTTP-таймаут — через `--web-timeout`
(по умолчанию 10 секунд, больше внутреннего 5-секундного ожидания прошивки).
URL может содержать HTTP-порт, например `http://192.168.1.50:8080`.
Пароль и session ID не выводятся в журнал. HTTP-прокси ОС не используются;
это не устраняет блокировку маршрутов VPN. Редиректы запрещены.
HTTP без TLS передаёт учётные данные открыто: использовать только доверенный стенд.

`--web-url` необязателен для обычных сценариев. Web-сценарии без него завершатся
ошибкой подготовки, ничего не меняя. Не выбирать `all` для обычного прогона,
если web-стенд не подготовлен. Web-тесты пока не поддерживают параллельный
координатор (`--can-ports`/`--udp-ports`) и отладочный ответчик `--debug`.

## Результат и восстановление

В консоли выводятся HTTP-шаг, подтверждение CAN и итог `9.1.1: OK/FAIL`
или `9.1.2: OK/FAIL`. При несовпадении выводятся канал и два сырых значения:
`expected=0x...., CAN=0x....`.

В `finally` изменённые привязки восстанавливаются напрямую по CAN, без HTTP,
после чего заново проверяется снимок. Исходное состояние здесь — состояние
**после подготовки пресета, перед сценарием**. Параметры, значения датчиков,
ручные входы и аварии эти сценарии не изменяют.

HTTP-таймаут может произойти после применения команды. В этом случае выполняется
диагностическое CAN-чтение и восстановление, но HTTP-команда автоматически
не повторяется, а результат остаётся `FAIL`.
Ошибки восстановления и logout также не позволяют выставить `OK`.

В GUI отменять тест штатной остановкой сценария и дождаться сообщения
`original mappings restored and verified`.
При потере CAN/UDP, закрытии процесса или выключении симулятора восстановление
не гарантируется: проверить привязки вручную перед следующим запуском.
В headless-режиме приложение остаётся работать после сценария;
нажимать Ctrl+C только **после** итогового результата и восстановления.
Код завершения обычного headless-приложения не является отчётом сценария.

## Офлайн-проверки

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe -m unittest tests.test_web_client tests.test_mapping_client tests.test_web_binding_scenarios -v
C:\Tools\Python311\python.exe tools\validate_scenarios.py
```

Тесты используют локальный HTTP-сервер и подменённый CAN, не внешний контроллер.
Они проверяют формат команд, авторизацию, таймауты, отсутствие повторов,
обратные связи, отмену и отказ восстановления. Это не заменяет сетевой прогон
с реальной прошивкой xhcc_s62; его нужно выполнить отдельно на доступном стенде.
