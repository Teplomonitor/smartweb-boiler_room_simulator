# Подготовка руководства BRS

## Файлы

- `docs/user_manual.md` — рабочий источник актуального руководства.
- `docs/images/*.png` — семь пользовательских скриншотов и две схемы; в ODT изображения встраиваются, а не связываются с внешними файлами.
- `docs/images/can_connection.svg` и `udp_connection.svg` — векторные версии схем.
- `docs/BoilerRoomSimulator_Manual_updated.odt` — редактируемая офисная версия.
- `docs/BoilerRoomSimulator_Manual_updated.pdf` — версия для распространения.
- `BoilerRoomSimulator_Manual.odt` в корне — исторический документ, сборка его не меняет.

## Обновление текста и скриншотов

Редактируйте Markdown и сохраняйте изображения в `docs/images/`. Если имя PNG не меняется, достаточно заменить файл и повторить сборку. Новое изображение добавляется обычной Markdown-ссылкой на отдельной строке, с полной подписью рисунка. Нумерация рисунков задана в тексте, а не вычисляется автоматически.

Не включайте в изображения пароли, токены, персональные данные и настройки рабочих объектов. Предоставленные скриншоты сохраняются как есть: экспорт не ретуширует их и не подтверждает достоверность изображённого результата испытаний.

## Экспорт в ODT

Экспортёр использует только стандартную библиотеку Python и не импортирует BRS, GUI, CAN или сетевые клиенты:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe tools\build_user_manual.py
```

Поддерживается используемый руководством ограниченный поднабор Markdown: заголовки уровней 1–3, абзацы, маркированные и нумерованные пункты, блоки команд, жирный текст, inline-code, ссылки и PNG на отдельных строках. Таблицы, вложенные списки, HTML и произвольный Markdown не реализованы: для нового оформления потребуется расширить экспортёр или перейти на Pandoc.

ODT содержит формат A4, заголовки, ссылки оглавления, подписи и номера страниц. Оглавление — сформированный список ссылок на разделы без номеров страниц. Не нужно вручную исправлять его после изменения длины документа; оно пересоздаётся при сборке. OpenOffice/LibreOffice также позволяют вставить собственное автоматическое оглавление по заголовкам.

Изображения вписываются в ширину страницы с сохранением пропорций. В большом скриншоте параллельного прогона мелкие надписи удобнее читать с увеличением PDF или в оригинальном PNG. При необходимости замените его более крупным снимком отдельного окна.

## Схемы CAN и UDP

Для перерисовки схем нужен Pillow (дополнительная зависимость только инструмента документации, не приложения):

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe -m pip install -r requirements-docs.txt
C:\Tools\Python311\python.exe tools\build_user_manual.py --draw-diagrams
```

Схемы рисуются одним описанием в `draw_diagrams()` и одновременно сохраняются в SVG и PNG. Используются Windows-шрифты Arial. Меняйте описание в скрипте для согласованного обновления обоих форматов. Ручное редактирование SVG допустимо, но этот инструмент не растеризует произвольный SVG; отдельно обновите PNG и не запускайте `--draw-diagrams`, чтобы не перезаписать ручные изменения.

Схемы логические: цепи питания, распиновка, требования к изоляции и электрической безопасности в них не заданы. Они не заменяют документацию оборудования.

## Экспорт в PDF

Нужен установленный OpenOffice или LibreOffice. По умолчанию выбран обнаруженный OpenOffice 4:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe tools\build_user_manual.py --pdf
```

Для LibreOffice задайте путь явно:

```powershell
C:\Tools\Python311\python.exe tools\build_user_manual.py --pdf --soffice 'C:\Program Files\LibreOffice\program\soffice.exe'
```

Полная сборка схем, ODT и PDF:

```powershell
C:\Tools\Python311\python.exe tools\build_user_manual.py --draw-diagrams --pdf
```

Конвертер использует отдельный временный профиль офиса, не закрывает открытый пользовательский Writer и не меняет старый документ. Сборка заменяет только две экспортированные версии и, при `--draw-diagrams`, две схемы PNG/SVG. Закройте обновлённый ODT/PDF перед повторной сборкой, если редактор блокирует файл.

OpenOffice экспортирует через `tools/manual_pdf_uno.py`, выполняемый встроенным Python офисного пакета; этот помощник совместим с его Python 2.7. Основной экспортёр и проверки запускаются документированным Python 3.11. Для офиса без встроенного Python используется CLI-конвертация LibreOffice.

**Изменения только в экспортированном ODT будут потеряны при повторной сборке.** Переносите правки в Markdown. Если нужна отдельная ручная офисная редакция, сохраните её под другим именем.

## Проверка перед распространением

1. Откройте PDF и просмотрите заголовки, переносы команд, все девять рисунков и подписи.
2. Проверьте читаемость скриншотов при предполагаемом размере печати.
3. Сверьте команды с `main.py --help`, имена CAN-профилей с `can.ini`.
4. Проверьте сохранность ODT и его встроенных изображений.
5. Изменение документа не подтверждает аппаратный прогон: не добавляйте заявление об успешном тестировании без реального испытания.

Автоматическая проверка ссылок, XML ODT, встроенных изображений и SVG:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe -m unittest tests.test_user_manual -v
```

Если в выбранном окружении доступен необязательный `pypdf`, дополнительно проверяются текст PDF, наличие всех команд и девяти изображений. Без него пропускается только этот тест. Для проверки PDF можно установить `pypdf` в отдельное временное виртуальное окружение, созданное проектным Python; он не требуется для сборки документа или работы BRS.

При первичной сборке от 5 ноября 2026 года сформирован PDF на 24 страницы с девятью рисунками. Все пять проверок документа прошли в изолированном окружении с `pypdf`; статический валидатор сценариев проверил 124 файла без ошибок и предупреждений. Это структурная проверка экспорта, не визуальная приёмка вёрстки и не испытание контроллера.
