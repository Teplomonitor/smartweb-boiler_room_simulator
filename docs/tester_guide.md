# Инструкция тестировщика BoilerRoomSimulator

## 1. Назначение программы

`BoilerRoomSimulator` используется для проверки прошивки SmartWeb-контроллеров по CAN-шине. Программа подключается к контроллеру, обменивается с ним сообщениями, предоставляет виртуальные входы и нагрузки, а сценарии автоматически изменяют входные условия и проверяют реакцию контроллера.

Задача тестировщика:

1. подключить контроллер к ПК через CAN-адаптер;
2. запустить экземпляр программы;
3. убедиться, что контроллер найден и его программы загрузились;
4. выбрать один или несколько сценариев;
5. дождаться результатов;
6. сохранить результаты и оформить отчёт по прошивке.

> Программа тестирует поведение подключённого контроллера. Она не прошивает контроллер и не заменяет процедуру обновления firmware.

## 2. Что требуется для работы

- ПК с Windows;
- установленный Python 3.11. Например, по пути `C:\Tools\Python311\python.exe`;
- установленный пакет зависимостей проекта;
- CANable GS-USB или совместимый CAN-адаптер;
- контроллер с установленной тестируемой прошивкой;
- кабель CAN и, при необходимости, общий GND;
- два терминатора по 120 Ом — по одному на каждом конце физической CAN-шины.

В проекте используется скорость CAN **20 000 бит/с**. Она должна совпадать с настройками подключённого контроллера и остальных устройств на шине.

## 3. Подключение CAN-адаптера

Подключите:

- `CANH` адаптера к `CANH` контроллера;
- `CANL` адаптера к `CANL` контроллера;
- `GND`, если он требуется для конкретной схемы подключения.

Перед запуском закройте другие программы, которые могут использовать этот CAN-адаптер или менять скорость CAN.

### Установка драйвера и зависимостей

Для адаптера, который отображается в Windows как **canable gs_usb**, должен быть доступен драйвер, совместимый с PyUSB. Если адаптер не обнаруживается, установите для него через Zadig драйвер WinUSB или libusbK.

Установите зависимости из корня проекта:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe -m pip install -r requirements.txt
```

### Проверка адаптера

До запуска программы проверьте, что адаптер виден системе:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe tools\list_gs_usb.py
```

Утилита только перечисляет найденные GS-USB-адаптеры и не передаёт CAN-сообщения. Индекс адаптера используется в профиле `can.ini`.

В стандартной конфигурации:

| Профиль | Индекс адаптера | Назначение |
|---|---:|---|
| `canable0` | 0 | первый обнаруженный GS-USB-адаптер |
| `canable1` | 1 | второй обнаруженный GS-USB-адаптер |

Индексы зависят от порядка обнаружения USB-устройств. После переподключения адаптеров порядок может измениться, поэтому при проблемах повторите проверку.

## 4. ID контроллера

ID контроллера назначается случайным образом в диапазоне от **1 до 255**.

### Один контроллер на одном CAN-адаптере

Это рекомендуемый и обычный вариант. Запускайте программу с `--id 0` или не указывайте параметр `--id` вообще:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --can canable0 --id 0
```

При `--id 0` программа не фильтрует найденные адреса и работает с первым подходящим контроллером, который ответил на CAN-шине.

Убедитесь, что на шине действительно находится только один контроллер. Иначе программа может выбрать не то устройство.

### Несколько контроллеров на одной CAN-шине

Если на одной шине находятся несколько контроллеров, укажите точный ID нужного устройства:

```powershell
C:\Tools\Python311\python.exe main.py --can canable0 --id 37
```

Значение должно быть числом от 1 до 255. Перед тестом зафиксируйте ID контроллера в отчёте.

## 5. Запуск программы

Всегда выполняйте команду из корня проекта.

### Запуск с GUI

GUI включён по умолчанию:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --can canable0 --id 0
```

### Запуск без GUI

Режим без окна пригоден для запуска в отдельном терминале или на ПК без установленного wxPython:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --no-gui --can canable0 --id 0
```

В этом режиме результаты и сообщения нужно отслеживать в консоли.

### Проверка запуска

После запуска программа:

1. открывает CAN-интерфейс;
2. ищет контроллер;
3. выводит в журнал найденный ID;
4. подключается к программам контроллера;
5. запускает симулятор и поток сценариев.

Если контроллер не найден, проверьте питание, проводку, скорость CAN, выбранный профиль адаптера и отсутствие другой программы, занявшей CAN-интерфейс.

## 6. Запуск сценариев

### Запуск одного сценария

В GUI откройте:

**Scenario → нужный сценарий**

После выбора сценарий перейдёт в состояние подготовки, затем начнёт выполняться.

### Запуск всех сценариев

Выберите:

**Scenario → all**

Сценарии будут выполняться последовательно, а не одновременно.

### Выбор нескольких сценариев

Выберите:

**Scenario → Select scenarios...**

В открывшемся окне:

1. отметьте нужные сценарии;
2. при необходимости используйте **Select all** или **Clear all**;
3. нажмите **Run selected**.

Список выбора сохраняется для текущего профиля в `settings.ini`. Если нужно изменить набор тестов, откройте это окно повторно и обновите отметки.

Тестировщик не выбирает preset вручную. Каждый сценарий сам определяет требуемую конфигурацию и при необходимости загружает соответствующий preset во время подготовки. Перед началом проверки дождитесь завершения подготовки сценария и перехода в состояние `SCENARIO RUNNING`.

### Запуск сценария из командной строки

Для запуска всех сценариев при старте программы:

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --can canable0 --id 0 --scenario all
```

Для запуска одного сценария через командную строку требуется передать путь к файлу сценария. Для обычной работы тестировщика удобнее выбирать сценарии через GUI, где программа показывает доступный список.

## 7. Состояния сценария

В верхней части GUI отображается состояние текущей проверки:

| Состояние | Значение |
|---|---|
| `SCENARIO PREPARING` | сценарий подготавливает конфигурацию и необходимые программы |
| `SCENARIO RUNNING` | сценарий выполняется; ручное управление входами заблокировано |
| `SCENARIO FINISHED` | выбранная последовательность завершена |
| `SCENARIO FAILED` | сценарий не удалось запустить или произошла ошибка |
| `SCENARIO STOPPED` | выполнение остановлено пользователем |

Итог каждого завершённого сценария выводится в журнале с его checklist ID, результатом и длительностью, например `3.11.6: OK` или `3.11.6: FAIL`.

Во время выполнения сценария не изменяйте вручную входы и параметры, если это не предусмотрено инструкцией к конкретной проверке. После завершения или остановки сценарий должен восстановить ручные входы и вернуть доступ к элементам управления.

## 8. Остановка сценария и программы

Чтобы остановить текущий сценарий, выберите:

**Scenario → Stop**

Чтобы полностью завершить программу:

- выберите **File → Exit**;
- либо закройте окно GUI;
- либо нажмите `Ctrl+C` в консоли.

Не отключайте контроллер и CAN-адаптер во время активного обмена, если это не требуется аварийной проверкой. При принудительном отключении обязательно отметьте это в отчёте.

## 9. Запуск нескольких экземпляров

Один процесс программы использует один CAN-интерфейс. Один процесс нельзя использовать для параллельного тестирования нескольких контроллеров.

Для параллельной работы запустите отдельный процесс для каждого контроллера и подключите каждый процесс к своему CAN-адаптеру. Например, в двух разных окнах PowerShell:

**Первый контроллер:**

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --can canable0 --id 0 --udp 31987
```

**Второй контроллер:**

```powershell
Set-Location C:\development\BoilerRoomSimulator
C:\Tools\Python311\python.exe main.py --can canable1 --id 0 --udp 31988
```

Для каждого процесса:

- используйте отдельный CAN-адаптер;
- проверьте, что адаптеры имеют разные индексы;
- используйте отдельный UDP-порт, если включён CAN-over-UDP bridge;
- при нескольких контроллерах на одной шине указывайте разные точные ID;
- не запускайте два процесса на одном CAN-адаптере.

Текущая версия не поддерживает один процесс, который одновременно тестирует разные сценарии на разных контроллерах. В каждом процессе сценарии выполняются последовательно и относятся к одному подключённому контроллеру.

## 10. Сохранение логов

Чтобы сохранить графики и журналы программ, выберите:

**File → Save log** или нажмите `Ctrl+S`.

При ошибке сценария программа также сохраняет журнал, связанный с checklist ID сценария. Не удаляйте эти файлы до оформления отчёта.

Для каждого тестового запуска сохраняйте:

- консольный журнал;
- логи программ и графики;
- версию прошивки контроллера;
- список запущенных сценариев;
- сообщения об ошибках.

## 11. Типовой чек-лист тестировщика

### Перед запуском

- [ ] Контроллер подключён и включён.
- [ ] CANH, CANL и GND подключены правильно.
- [ ] Терминация CAN-шины установлена корректно.
- [ ] Скорость CAN установлена в `20 000 бит/с`.
- [ ] Другие CAN-программы закрыты.
- [ ] CAN-адаптер виден через `tools\list_gs_usb.py`.
- [ ] Выбран правильный профиль: `canable0` или `canable1`.
- [ ] На шине находится только нужный контроллер либо известен его точный ID.

### Во время теста

- [ ] В журнале найден ожидаемый контроллер.
- [ ] В GUI отображается правильный ID и набор программ.
- [ ] Сценарий перешёл в состояние `SCENARIO RUNNING`.
- [ ] Ручные входы не изменяются без указания сценария.
- [ ] Зафиксированы сообщения об ошибках и предупреждения.
- [ ] Дождались итогового состояния сценария.

### После теста

- [ ] Записан результат каждого сценария: `OK`, `FAIL` или `STOPPED`.
- [ ] Сохранены логи и графики.
- [ ] Контроллер возвращён в безопасное состояние.
- [ ] Остановлены сценарий и программа.
- [ ] Заполнен отчёт по прошивке.

## 12. Диагностика проблем

### Программа пишет `controller not found`

Проверьте:

1. включён ли контроллер;
2. правильно ли подключены `CANH` и `CANL`;
3. подключён ли общий `GND`, если он нужен;
4. совпадает ли скорость CAN;
5. выбран ли правильный профиль `--can`;
6. виден ли адаптер через `tools\list_gs_usb.py`;
7. не используется ли адаптер другой программой;
8. не требуется ли указать конкретный `--id`.

### Найден не тот контроллер

Если на CAN-шине несколько контроллеров, режим `--id 0` может выбрать первый ответивший контроллер. Повторите запуск с точным ID:

```powershell
C:\Tools\Python311\python.exe main.py --can canable0 --id 123
```

### Сценарий не запускается

Проверьте:

- не выполняется ли уже другой сценарий;
- завершилась ли подготовка сценария;
- поддерживает ли выбранная конфигурация требуемые программы сценария;
- не отключился ли контроллер;
- нет ли ошибки импорта или ошибки в журнале.

Одновременно запустить второй сценарий нельзя: сначала остановите текущий через **Scenario → Stop** или дождитесь его завершения.

### Адаптер не открывается

Проверьте:

- правильность драйвера GS-USB;
- индекс адаптера;
- отсутствие второго процесса, использующего этот адаптер;
- соответствие профиля и физического устройства;
- поддержку скорости 20 000 бит/с адаптером.
