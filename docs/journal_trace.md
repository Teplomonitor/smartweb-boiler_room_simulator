# Трассировка CAN-обмена журнала

Установите `BRS_JOURNAL_TRACE=1` в окружении процесса симулятора. Переменная
наследуется параллельными рабочими процессами. Для отключения удалите её или
задайте другое значение. По умолчанию трассировка выключена.

Например, для выборочного запуска через UDP:

```powershell
Set-Location C:\development\BoilerRoomSimulator
$env:BRS_JOURNAL_TRACE = '1'
C:\Tools\Python311\python.exe main.py --no-gui --udp-ports 31987 --scenarios C:\development\BoilerRoomSimulator\scenario\list\journal\scenario_journal_9_1.py
Remove-Item Env:BRS_JOURNAL_TRACE
```

Убедитесь, что выбран нужный контроллер и его можно использовать для испытаний:
сценарии могут сбрасывать и загружать конфигурацию, менять входы, параметры или
часы. Чтение журнала также может помечать записи отправленными на контроллере.

Строки `JOURNAL_TRACE` находятся в обычном журнале консоли; при параллельном
запуске — в `log/parallel_can_*/worker_*/console.txt`. `time` — время хоста в
секундах Unix с микросекундами. `TX_ATTEMPT` означает попытку отправки, а не
подтверждение доставки; `RX` содержит только подходящие под активный фильтр
ответы контроллера, а `RX_UNMATCHED` — журнальные ответы с другим ID контроллера.
`UDP_TX` означает успешный вызов отправки датаграммы, но не её доставку;
`UDP_RX` — получение датаграммы мостом. `UDP_NO_DESTINATION` означает, что
адресатов нет, а `UDP_TX_ERROR` — ошибку системного вызова отправки.
Строки `retry_incomplete` отмечают повтор запроса с прежним курсором. Читатель
повторяет запрос не более двух раз при отсутствии или неполноте ответа,
сохраняя фрагменты между попытками. Таймаут не подтверждает конец журнала:
для этого необходим STATUS с CRC и временем текущего курсора. Фрагменты могут
поступать в любом порядке; проверяются комбинации по CRC, а дубликаты текущего
курсора игнорируются. Число вариантов фрагментов ограничено; неоднозначные
CRC-совпадения и переполнение буфера считаются ошибкой, а не концом журнала.
Поскольку не все фрагменты содержат идентификатор записи, CRC не исключает
необнаружимую коллизию при перемешивании разных записей.
Для кадров записываются расширенный CAN ID, длина и сырые
байты. Дополнительные строки показывают курсор, полученные и повторные записи,
неполный ответ и достижение пределов. Это диагностический вывод, а не
полный захват всей шины; время строк может немного отличаться от времени кадра.
